# Long runs and handoff

Load this file when running `deploy`, `destroy`, or `spa run`, or when Phase 14 option A hands off to `/spa`. Do not load it for config design, validation-only, or contributor work.

## Long runs

`deploy`, `destroy`, and `spa run` write one sentence to stderr when the phase or host changes. The 20-second heartbeat repeats `Still …` from the last phase sentence (for example `Still downloading Splunk on cm.`). Stdout is the final JSON envelope. When the current directory is the environment, start `spa --agent deploy --yes` there, and the same form for `destroy` and `run NAME`. Do not pass `--env`, and do not run `spa environment list`. From any other directory, pass `--env NAME` on that same command. Do not pass `-v` or `--ansible-output`. Do not read `.spa.yml`, the terminal folder, `lib/spa`, or docs. Do not grep the repo. Do not list tools, and do not open a todo list.

Start that command once: `spa --agent deploy --yes` from the env dir. No `2>&1`, no `| grep`, no `| head`/`tail`, no `-v`, no `--ansible-output`. Deploy and destroy share one lock. While one of them is running, the others are refused. The error names the running command, for example `A deploy is already running.` Report that sentence and stop. Do not start one of the other two. The lock ends when that process ends, including when it is aborted. Wait in one call until `"ok":` or the process exits. Do not poll every second, and do not put the sentence list into the wait pattern. If a sentence is already visible on the command, repeat that exact line once. Do not read the terminal file, and do not call other tools. Do not run `spa validate` unless the user asked for it. Forward each `Still …` heartbeat as it appears. When the process exits, report the envelope in one sentence. Do not wait on the word `phase` or a Terraform banner.

Cursor: background the shell, `AwaitShell` once with `pattern` `"ok":` and a long `block_until_ms` (for example 1200000). Repeat that wait if still running. Forward each stderr sentence as it appears (`Planning the infrastructure.`, `Creating HOST.`, `HOST is up.`). Do not invent a grep pattern. Do not use shell `sleep`, and do not read the terminal file. The sentences are for reporting only; they are not the wait pattern. Same wait rules for destroy.

Creating hosts and destroy: `Planning the infrastructure.`, `Creating HOST.`, `HOST is up.`, `Destroying HOST.` Deploy: `Host is prepared.`, `Hosts are already prepared.`, `Downloading Splunk on HOST.`, `Splunk is already downloaded on HOST.`, `Extracting Splunk on HOST.`, `Splunk is already extracted on HOST.`, `Configuring the cluster manager.`, `The cluster manager is already configured.`, `Configuring Splunk.`, `Installing cluster manager apps.`, `Installing ITSI.`, `Installing apps on HOST.` A role's already-configured sentence is printed when that role's own tasks finish with nothing changed. Opening checks do not count, and baseconfig between those tasks does not finish the role. A role play with no matching hosts is silent. `spa run` uses those same sentences, plus `Upgrading indexer HOST.`, `Restarting Splunk on HOST.`, and `Running TITLE.` for any other playbook.

`spa deploy` creates missing hosts if needed, then runs an Ansible ping with become for the selected hosts after you confirm and before `deploy_site.yml`, then compares `splunk_architecture` with the machine. The expected value is the host override, then that host's `splunk_environments` entry, then `splunk_defaults`, then `amd64`. A failed check fails deploy; it does not recreate hosts. `spa hosts check` is that check on its own. `spa deploy --hosts ROLE` includes every config host in that role. Before `spa run` of a playbook that needs root, run `spa hosts check`.

`external` hosts are registered with `spa hosts register NAME --ssh-host HOST --user USER --key PATH --yes`, which checks SSH and writes the SSH host, user, and key only in `inventory/hosts`. Add `--ssh-port PORT` when SSH is not on port 22. Add `--ip-addr ADDRESS` when Splunk hosts reach that machine on a different address than SSH. Omit `--ip-addr` to use the SSH host for both. The config only needs `external:`. `spa validate` stays the local config check. `spa deploy` pings with become and compares `splunk_architecture` with the machine before the playbook for AWS, VirtualBox, and external hosts. The expected value is the host override, then that host's `splunk_environments` entry, then `splunk_defaults`, then `amd64`. `spa hosts check` is that check without deploying. Run it before `spa run` when the playbook needs root. Deploy and destroy do not create or terminate external hosts. Suspend and resume report that SPA does not own power for those hosts.

## Handoff from spa-create-config

When a design ends with validation passed and the operator picks option A, run these steps here. Each step waits for its own yes in chat.

1. **Infrastructure plan (read-only).** `spa --agent config get terraform.aws` and `spa --agent config get splunk_hosts`. List region, instance type, volume size, AMI, and host roles. SPA has no separate Terraform plan preview.
2. **Deploy gate.** Show the app names from `spa --agent config get splunk_app_deployment` and the license file from `splunk_defaults` (or trial-only). Report Splunkbase credentials as set / not set only. Print this copy-paste hint for another terminal (do not wait for the operator to start it, and do not put it on `data.next` as a required AskQuestion): `spa --env NAME logs --follow --wait --ansible-output --color`. Always include `--env NAME` so it works from any directory. AskQuestion: **Deploy (creates hosts if needed)?** Yes / No. The Phase 14 "yes" is not this gate.
3. On yes, run `spa --agent deploy --yes` under Long runs. One `--yes` covers create plus Splunk when hosts are missing. Report the envelope in one sentence and the Splunk Web URL from the deploy result. Do not invent a URL. Do not open `data.log` unless asked. Never pass `-v` on the agent deploy.

Stop at the first failure and report it. Never pass `-v`. From a directory other than the environment, pass `--env NAME`. One yes per gate.
